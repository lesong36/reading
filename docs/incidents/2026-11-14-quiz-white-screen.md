# P0：点击答题选项后白屏

## 结论与影响

用户截图证实：`reader_quiz_progress_rfd5-09-Unit-9-The-Theremin` 写入 localStorage 时抛出 QuotaExceededError。答题保存位于 React useEffect，异常未隔离，造成根界面卸载。受影响条件是同源存储已满或不可写；具体受影响人数、开始时间、存储占用来源无遥测证据，不作推断。Babel 的大文件提示不是此次直接原因。

## 根因与防线缺口

1. 把有容量和访问限制的浏览器存储当作永远成功的操作。
2. 题目及多个偏好保存绕过已有保护函数；原保护仅处理配额异常，其他存储异常仍向上传播。
3. 书架等较大数据与进度共享 localStorage 配额，已有 OPFS 存储不能保证小记录写入成功。不能据此认定书架必然是本次占满来源。
4. 缺少存储耗尽、禁止访问的自动回归；保存失败没有明确提示。
5. 验证中另发现：文章对象更新会重复恢复答题状态并切回阅读；恢复与保存副作用同轮运行还可能把旧文章进度写入新文章。此次加入恢复身份及首轮保存保护。

## 修复

所有入口中的 localStorage 写入统一经异常隔离，不再让保存失败传播到 React。答题记录写入失败时保留内存最新副本并尝试独立的 sessionStorage；恢复及云同步枚举同时读取备用副本。成功写回主存储时删除旧备用副本。保留现有数据，不自动删书架、答案或用户配置。

保存失败显示持续告警。标签页备用保存可以承受同标签页刷新，但不保证关闭标签页后保留；两个存储都不可写时仅保留当前页面内存。不要宣称临时存储等同永久保存，也不宣称未登录或网络断开时云同步成功。

## 验证及防复发

- Node 回归覆盖 QuotaExceededError、SecurityError、正常写入、备用最新进度与云枚举。
- 静态回归禁止应用入口出现绕过保护函数的 localStorage.setItem。
- 浏览器脚本注入真实 Storage.prototype 写入异常，点击实际题目选项，检查页面仍可操作、告警可见、无未捕获异常；单独检查备用记录和刷新恢复。
- GitHub Actions 对 push/PR 执行存储回归，防止同类裸写入回归。此检查不等同分支保护；有权限者仍可能绕过流程。
- 此次发布基于生产 main，只包含故障修复、验证与报告，不包含开发目录其他未提交功能。
