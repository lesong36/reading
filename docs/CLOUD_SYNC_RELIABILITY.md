# 跨浏览器记录更新不及时：根因与修复

## 现场事实

Chrome 本机有《The Theremin》8道答案及交卷记录；只读云端查询确认8道答案已上传。Edge 曾显示本机2道答案，之后重新加载会话/云端拉取后显示完整记录。两个浏览器使用同一账号，不能把问题归因为账号不同。

诊断只执行了只读查询，没有人为上传答案。恢复恰好发生在提问期间，不代表提问是同步触发器。旧版缺少触发原因日志，无法唯一还原当时是哪一次刷新/会话恢复/重试完成拉取。

## 已确认的代码缺陷

1. 答题状态与阅读位置不在上传触发依赖中，可能等到生词、完成记录等其他状态改变才上传。
2. 返回浏览器的可见事件只维护本机数据；云端读取主要依赖登录初始化、网络恢复和重试，没有前台周期校验。
3. 上传进行中会直接丢弃新的触发，缺少后续补发。
4. 等待读取时的旧上传快照可能覆盖刚写入的新答案；整篇时间戳不能正确合并两设备对不同题目的修改。
5. 拉取响应携带旧文章身份，切换文章/账号时缺少足够的应用边界。
6. “生词已确认”状态不能证明全部学习记录已同步，且没有明确的最近成功时间。

## 2026.11.14.3 修复

- 每次答题、交卷、定位修改、阅读位置及偏好变化可独立触发上传，800毫秒合并短时变化。
- 窗口获得焦点、页面可见、网络恢复时拉取；前台在线时每30秒校验，重复可见事件2秒内合并。
- 上传在途时标记待补发，完成后使用最新状态再同步；读取返回后重新读取本机答案，而非回写旧快照。
- 答案与定位分别保存逐题修改/删除版本，重置带删除边界；阅读位置逐文章比较更新时间，防止旧设备回退无关题目或文章。
- 响应应用前复核账号代次和当前文章身份；旧账号请求不能更新当前状态。
- 同步请求15秒超时，失败走现有退避重试。状态区区分待同步、正在同步、失败及最近确认成功时间。

云端JSON增加版本元数据，保留现有表、权限和接口。第一次更新代码需要两个浏览器加载新版本；旧客户端不理解逐题版本，不能保证与长期不更新的旧页面并发编辑时拥有同等冲突保护。设备时钟严重偏差、同题同时修改仍按版本比较和稳定规则取一方；本次不宣称分布式强一致。

## 验证

独立 Chromium 会话共享模拟云端，避免修改用户真实记录。覆盖只答题就上传、切回另一浏览器无需刷新、慢上传和慢读取期间继续答题、不同题目合并、旧快照保护、账号切换隔离、状态时间与空闲无上传循环。另验证同步途中切换文章及不同文章阅读位置不会互相污染。

发布完成以Pages成功部署、线上版本及隔离浏览器自动同步回归为准。iPad Safari 真机和真实账号网络中断重连尚未由模拟云端测试替代。

本地最终验证：56/56 Node测试通过；生产独立回归23/23通过。生产入口双浏览器完整场景通过，包括慢查询期间再次答题、切换文章防串写、切换账号取消旧请求以及不同文章阅读位置保护。账号恢复期间显示“恢复登录中”，恢复失败明确报告，不再把尚未完成恢复当成确定未登录。
