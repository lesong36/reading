# 阅读达人：篇章阅读产品规划（V2）

> 状态：规划讨论稿；未进入实现。
> 决策：原有 Article Reading Model V1 已被否定，不作为本规划的前提或迁移目标。

## 1. 已确认的产品边界

ReadMaster 中有三项并列、但不应混在一起的阅读能力。

| 能力 | 阅读单位 | 用户目的 | 系统职责 | 不做什么 |
| --- | --- | --- | --- | --- |
| 句子解析 | 例句 / 句子 | 看懂词、短语、句法和句内意义 | 给出可操作的句子级分析与支撑 | 不替代段落或全文理解 |
| 做题 | 文章自带题目 | 定位、作答、自动判卷 | 呈现题目、定位原文、评分与复盘 | 不把题目流程假装成阅读教学 |
| 篇章阅读 | 段落、段间、全文 | 学会用文章结构建构意义 | 用专家文章模型编排例子、引导和反馈 | 不生成另一份标准化练习册或答案面板 |

因此，“篇章阅读”不是句子解析的放大版，也不是做题入口的改名。它是一套以**文章自己的段落和篇章位置为例子**的阅读教学工作区。

一句产品定义：

> 孩子在原文中观察、尝试、回看并组织段落与全文意义；经过审核的专家文章模型只决定“下一步该看哪里、能给什么支撑、怎样反馈”，不在孩子开始前把结论交给他。

## 2. V1 的处理决定

V1 作为已完成的技术实验保留，以便回溯；不再作为产品迭代基础。

### V1 明确不再延续的部分

- 以 `choose_main_idea`、`choose_heading` 等六类题目组成主流程；
- Runtime 从自由的 `function.type`、`relation_to_previous.type` 猜儿童分类；
- Runtime 从 `signals` 和 `key_details` 反推出可接受证据；
- 一段只有一个、且只能连接前段的关系；
- 用一个平面的全文结构标签驱动整篇体验；
- 把专家标注直接转化为孩子需要选择的“正确答案”。

这些问题在现有原型中可见：`index.html` 的选项构造与启发式归一逻辑（约 4460–4535 行），以及把“篇章阅读”呈现为二遍多项选择流程的区域（约 8055–8182 行）。V1 文档与其导入、校验脚本只作为历史参考：
`docs/ARTICLE_READING_MODEL_V1.md`、`scripts/generate-article-reading-model.mjs`、`scripts/validate-article-reading-model.mjs`。

### 立即的产品约束

- 不继续给 120 份 V1 sidecar 扩充规则或批量发布；
- 不把 V1 的正确率、完成率当作篇章阅读学习效果；
- 在 V2 的人工标注样本和教学流程通过审阅前，不以 V1 UI 代表正式功能。

## 3. 篇章阅读的核心：专家模型如何被应用

专家文章模型不是孩子看到的一张“文章答案图”，而是教学引擎的受控输入。

```text
原文的稳定位置
      ↓
经过审核的专家文章模型
  ├─ 意义节点：哪些意思由哪些段 / 句承载
  ├─ 关系：解释、举例、因果、对比、顺序……怎样连接
  ├─ 组织：哪些段构成一个部分，全文怎样展开
  └─ 修辞目的：作者为什么此处介绍、解释、转折或收束
      ↓
教学编排（不是题库）
  ├─ 此刻让孩子看哪一个范围
  ├─ 可以点击、选择、拖动或连接什么
  ├─ 何时给哪一级提示
  └─ 尝试后如何用原文解释、允许修正
      ↓
孩子的候选理解、证据选择、连接和文章地图
```

专家模型必须先于 Runtime 冻结。P920 可以在导入期产出**草稿**，但不能在阅读时临时解析，也不能未经教研审核就成为教学真值。

## 4. MVP 的儿童体验：不是“先给答案，再做题”

MVP 只做小学说明文，围绕一个完整但小的阅读回路。每一步都是同一篇文章里的段落或全文例子。

```text
看范围 → 留下一个候选理解 → 回原文找支撑
       → 看它怎样接到下一部分 → 放进文章地图 → 回看并修正
```

### 4.1 每个教学例子的固定骨架

“例子”不是静态讲解卡。它必须是一个可完成、可改正的微互动。

| 环节 | 孩子看到的内容 | 专家模型的作用 | 系统不能做的事 |
| --- | --- | --- | --- |
| 聚焦 | 明确的段落 / 段落对 / 全文范围 | 给出要看的 source scope | 一开始显示段意或正确关系 |
| 尝试 | 点、选、拖、连、点击原文 | 提供有限且有语义差异的操作对象 | 把自由标签临时猜成答案 |
| 支撑 | 可点击原文、分级提示 | 指向真实可接受的 evidence sets | 只用单一“关键词”判对错 |
| 回看 | “为什么这一处能支持你的想法” | 给出与本次选择相关的解释 | 只显示“对 / 错” |
| 修正 | 撤销、替换、再次尝试 | 记录候选与修正 | 错一次后锁死或泄露未选答案 |
| 组织 | 便签、箭头、段落卡 | 规定可成立的连接与层级 | 直接把专家地图画完给孩子 |

### 4.2 MVP 的四个阅读动作

儿童界面不展示术语，但内部由以下动作构成：

1. **段落意思**：先说“这段主要在讲什么”，形成可修正的候选便签；
2. **原文支撑**：回到这一段，点出一句或一组句子说明候选不是凭空猜的；
3. **段间衔接**：比较两段便签，连出“后面为什么接着这样讲”；
4. **全文组织**：把已经确认或暂存的段落卡组成若干部分，最后形成全文意思的候选。

预测、推断和作者意图不是 V2 MVP 的独立“题型”。它们只在某篇文章确有合适模型节点、且能帮助上述四个动作时，作为低风险提示或延伸。

### 4.3 脚手架的撤除

同一阅读动作应以不同支撑水平出现，而不是每篇永远四道选择题。

```text
看见范围和候选卡
  → 在少量卡片中选择
  → 自己点原文并拖卡连接
  → 可选语音 / 简短表达，并回看证据
```

系统记录的是“候选 → 证据 → 修正 → 组织”的过程，而不是只记录最终是否答对。

## 5. MVP 的专家模型最小需求

此处是**标注需求**，不是最终 JSON Schema。一个经过审核的说明文样本至少需要：

| 模型面 | MVP 最小信息 | 为什么需要 |
| --- | --- | --- |
| TEXT | paragraph、sentence、span 的稳定 ID | 让所有提示和证据回到原文 |
| Semantic | central / major / supporting ideas，及各自 source scope | 支持段意候选与全文组织 |
| Discourse | 有向 relation，连接两个 ideas 或 spans，带 relation evidence | 支持段间“为什么这样接” |
| Organization | section 范围和成员段落 | 支持从段落卡到全文部分 |
| Rhetoric | 有限的段落功能枚举，附 source scope | 只在教学上确有价值时解释作者安排 |
| Pedagogy | 顺序、目标、可接受操作、提示、修正反馈和解锁条件 | 让 Runtime 只渲染与记录 |

`content / analysis / pedagogy` 的顶层分离保留；其具体 V2 shape 必须由人工样本反推，而不是直接从 V1 字段改名。

## 6. 与当前 ReadMaster 的入口关系

```text
打开文章
├─ 句子解析：需要时解决一个句子怎么读
├─ 做题：完成文章自带题目，定位、判卷、复盘
└─ 篇章阅读：沿原文进行段落到全文的意义建构
```

三者共享同一篇原文和稳定 ID，但不共享步骤状态：

- 句子解析的完成不等于篇章阅读已完成；
- 做题的对错不等于孩子建立了文章模型；
- 篇章阅读不应以“先完成句子解析”作为入口门槛；孩子可在卡住时跳回句子解析，再回到原来的篇章位置；
- 篇章阅读中的便签、证据、连接和修正，属于个人学习过程；文章的专家模型永远不被孩子的答案覆盖。

## 7. 实施规划（尚不执行）

### Phase 0：冻结并隔离 V1

1. 在文档中标记 V1 已拒绝；
2. 停止新增或发布 V1 sidecar；
3. 后续实现时将 V1 tab 视为实验入口，不与 V2 共用同一个“篇章阅读”正式入口。

完成标准：没有新方案依赖 `relation_to_previous`、自由 `function.type` 或 Runtime 推断答案。

### Phase 1：一个人工审核的专家模型样本

1. 从现有书架选一篇 3–5 段、结构清楚的小学说明文；
2. 人工标出 Idea、Relation、Section、Function 与 source scopes；
3. 用这篇文章检验每个标注是否能生成一个“孩子先尝试、再看支撑、可以修正”的互动；
4. 不合格的模型字段删除或重新定义，不以批量 parser 输出补洞。

完成标准：一位教研者能只看模型解释“这一互动教什么、孩子在原文哪里操作、何时给反馈”。

### Phase 2：从样本反推最小 Schema 与教学编排

1. 为专家模型冻结有限枚举和引用规则；
2. 为每个教学例子写明确的 `target`、`accepted actions`、`evidence sets`、`hint ladder`、`feedback policy`；
3. 写 validator fixture，拒绝无 source scope、无修正路径、或靠 Runtime 猜答案的教学数据；
4. 决定哪些 learner events 需要长期保存。

完成标准：Runtime 读取教学编排即可渲染 MVP，不再包含标签正则归一和证据猜测逻辑。

### Phase 3：单文 MVP 与可用性验证

1. 在现有文章工作区增加独立的 V2 篇章阅读入口；
2. 实现四个阅读动作及可逆操作；
3. 保持句子解析与做题入口不变；
4. 用真实儿童 / 教研试读检验：孩子是否理解此刻该做什么，是否能在错后继续，是否会把它误认为普通做题。

完成标准：孩子在未先看答案的情况下完成一次“候选—证据—连接—组织”回路；每一次反馈可指回原文；做题功能没有回归。

### Phase 4：小样本导入与审核工作流

1. P920 只生成 V2 草稿；
2. 教研审核后才能附着到文章；
3. 先扩到 3–5 篇结构差异明显的说明文；
4. 通过后再讨论 RFD1–6 / RE 的批量迁移。

完成标准：每篇文章的模型、教学编排、UI 行为和人工审阅记录可追溯；不因 Runtime 规则差异改变答案。

## 8. 可验证的验收标准

- 在篇章阅读中，孩子提交自己的第一次操作前，界面不显示对应专家结论；
- 每个可判定的互动都指定明确的 `target` 与引用原文的 `source scope`；
- 错误选择可撤销、替换或继续寻找证据，且未选项不以颜色泄露答案；
- 任何正式答案、关系和反馈均来自审核后的 `pedagogy`，Runtime 不用文本正则或临时 LLM 推断；
- 句子解析和文章做题的现有入口、定位、自动判卷行为保持不变；
- 一个 MVP 文章能支持段意、证据、衔接、组织四个动作，但不要求覆盖所有篇章技能；
- P920 失效或输出不完整时，文章仍可正常使用句子解析与做题，不显示半成品篇章阅读。

## 9. 下一轮应冻结的唯一问题

先不讨论 UI 细节，也不讨论批量解析。下一轮只需为一篇样本文选择并审阅：

> **专家文章模型中，哪些最小节点和关系，足以让孩子完成一次“候选 → 证据 → 衔接 → 组织”的阅读回路？**

这会决定 V2 Schema，而不是相反。
