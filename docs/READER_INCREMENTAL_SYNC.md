# ReadingMaster 增量同步：实施与发布验收

实施计划：[reader-incremental-sync.md](plans/reader-incremental-sync.md)。本文件随实际证据更新；“实现”“本地验证”“生产验收”分别记录。

## 协议与边界

ReadingMaster 独占 `reader_delta` 数据，不读取 VocabMaster 私有表。普通同步调用 `reader_delta_push` / `reader_delta_pull`；禁止接口失败时回退 `reader_sync_state` 全量读写或旧词库接口。

实体由账号、类型和稳定业务ID定位；操作具有唯一 operationID 与 baseVersion。答题事件追加且不可改写，当前答案投影与历史分开。删除保存墓碑，恢复必须明确指定。服务端同账号事务锁覆盖版本分配、变化插入和提交，因此不会使用可能晚提交的裸序号作为安全游标。

上传最多50条，客户端按完整JSON UTF-8请求100KiB拆批，服务端独立拒绝超限；下载按游标最多50条且受字节预算约束。单项超限保留原件与待确认操作并报告错误。

本机先提交IndexedDB再发送。确认ID才可移除outbox。收到变化与推进游标必须在同一个事务内提交。账号切换不能把共享页面旧状态当成新账号的初始数据。

## 发布顺序与回滚

1. 保留原云端快照、本机数据及旧版本资源；先在隔离数据库验证SQL与权限。
2. 部署新增协议，逐账号迁移；验证ID、数量、内容哈希后才启用旧客户端写保护。迁移失败保留原数据，可重入恢复。
3. 发布客户端和模块，核对各入口包含新脚本；桌面打包需同步该脚本。
4. 小流量观察：真实请求/响应字节、待确认积压、错误类别、最近成功时间。分别验证Chrome与Edge真实账号操作。
5. 发现异常停止扩大范围；保留新数据、操作确认和墓碑，修复后重放未确认队列。不得回滚成可以覆盖新记录的旧全量写协议。旧快照只用于核对与恢复，不能直接覆盖增量实体。

## 必须持续保留的检查

一万/十万历史新增一题只传变化，空闲不读旧快照，多设备仅拉游标后数据；断网、响应丢失、刷新、并发、乱序、过期游标、删除恢复、切账号不丢失不串号。迁移完整性独立审计，不以“已同步”界面替代证据。告警不能通过关闭提醒处理；区分本机持久化、网络与数据库超时，积压和恢复通知去重。

## 当前边界

本次替换了普通同步对整行快照的依赖，网络与服务端普通查询有界。跨标签页一致性仍会在本机操作前读取该账号的实体缓存，因此本机入队成本会随本机历史增长；不宣称本机十万记录操作成本恒定。完整初次迁移和审计允许遍历旧快照，普通同步不使用该路径。

无法确认归属的旧本机学习记录保存为迁移前备份，可在云同步设置导出；不会自动将上一账号或匿名记录上传给当前账号。超过单项大小上限的旧记录会明确停止迁移并保留原件，需要专门拆分处理，不会丢弃记录继续显示成功。

生产数据库和三个现有账号迁移已完成，客户端2026.11.16.2已发布。已登录浏览器真实业务流量仍待会话验证，不能据数据库核验宣称所有生产验收已完成。先部署数据库，再发布客户端；旧客户端写保护不能撤销作为回滚手段。

实际页面测试 `tests/reader-delta-ui-browser.py` 另覆盖答题产生小事件、慢拉取期间继续答题及A→B→A账号往返。网络为隔离假RPC，页面使用实际React界面。
