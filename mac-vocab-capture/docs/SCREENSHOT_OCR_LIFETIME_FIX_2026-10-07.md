# 截图 OCR 空白：临时图片生命周期修复

适用版本：0.2.77。

## 故障与原因

截图取词窗口的“识别原文”为空；截图问一问同时收到空白图片。公开英文测试段落本身可识别，字体和背景不是原因。

`ScreenshotRegionCapture` 从临时 PNG 创建 `CGImage` 后立即清理文件，OCR 则在回调返回之后异步执行。ImageIO 默认延迟解码，图片尺寸有效不代表像素已经加载。测试中的文件已删除时，返回的图片无法再识别文字，问一问生成的 PNG 也失去文字。

现在向 `CGImageSourceCreateImageAtIndex` 传入 `kCGImageSourceShouldCacheImmediately: true`，先解码像素，再继续清理临时文件。不增加依赖、不保留用户截图、不改变上传规则。选项语义见 [Apple ImageIO 文档](https://developer.apple.com/documentation/imageio/kcgimagesourceshouldcacheimmediately)。

## 可重复证据

新增 `ScreenshotOCRPipelineTests` 使用自身绘制的公开英文 PNG，不读取用户截图、配置、钥匙串或调用模型：

- PNG 从内存直接解码能够识别，排除空白夹具。
- 截图回调返回且临时文件已删除后，图片仍能识别。
- 正式截图取词 action 显示完整识别原文。
- 正式截图问一问 action 显示原文，且不自动调用模型。
- 问一问保留的原图再次 OCR 可读。

修复前第一个对照通过，其余四项失败；修复后五项全部通过。已有 OCR 与截图流程十项测试也通过。

隔离真实截图识别了完整 269 字符，耗时 0.19 秒。早期正式诊断在回调内保存原图，也能识别；这一保存操作提前触发了像素加载，因此它不能单独证明原流程正常。这正是组合回归测试补齐的缺口。

## 正式应用系统复测

用户在已安装的 0.2.77 按 `⌥A` 框选同一段公开英文。通过辅助功能读取正式问答窗口，原文完整显示 269 字符；勾选“参考原截图”后，DeepSeek Flash 正确解释了流式输出、响应性与 LLM 延迟的关系，不再回答图片为空白。该次请求首字 1.47 秒、总耗时 2.94 秒、输出 269 tokens；界面所示平均 TPS 91.6 含等待时间。

本次真实问答包含 OCR 原文和图片，不是单独图片模式；原图自身可读另由组合回归测试验证。上述数字是单次功能验收，不是性能基准。

第一次全量运行中，既有日志过期测试对“日志文件不存在”的断言失败。使用独立诊断目录重新运行全量后全部通过；未为本次 OCR 修复改动日志行为。该测试存在时间或日志写入干扰的风险，后续应独立处理。

Sublime/微信自动浮动取词兼容性仍按用户要求暂停，不属于本次修复。
