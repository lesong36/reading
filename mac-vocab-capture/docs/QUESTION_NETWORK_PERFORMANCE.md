# 问答网络路径与首字延迟验证（0.2.72）

2026-10-06，在当前 Mac、现有三个服务配置上对比系统 HTTP 代理与直连。发现 DeepSeek 可通过跳过系统 HTTP 代理缩短等待，已安装 0.2.72，并仅为现有官方 DeepSeek 配置启用直连。GPT、Claude 的配置保持原网络选择。原始脱敏结果见 [JSON](QUESTION_NETWORK_PERFORMANCE.json)。

## DeepSeek 三轮对照

| 路径 | 首字中位数 | 首字范围 | 总耗时中位数 | 成功数 |
|---|---:|---:|---:|---:|
| 系统代理 | 1.355 秒 | 0.997–1.693 秒 | 2.031 秒 | 3/3 |
| 直连 | 0.507 秒 | 0.238–1.195 秒 | 1.197 秒 | 3/3 |

这组首字中位数减少约 63%。两条路径使用同一模型、问题、原文、关闭思考设置及原有完整系统提示；没有通过删掉语法约束或减少原文来提速。计时从 Swift 调用开始到首个非空可见回答片段，不包含截图、OCR 或引擎启动；单个片段可能包含多个 token。

每条路径只有三次样本，不能承诺稳定达到 0.5 秒。较早的全模型初测中，DeepSeek 首次直连仍耗时 1.87 秒。安装后再次通过正式包内引擎和生产 Swift facade 调用，首字 1.113 秒、总耗时 1.648 秒，正确判定介词后应使用 me。网络与服务端仍有明显波动。

## GPT 与 Claude

全模型初测每个模型、每条路径各两次，失败样本也保留：

- GPT 系统代理：一次首字 3.088 秒，一次在诊断的 15 秒读取限时超时；直连两次均在 4 秒连接限时超时。
- Claude 系统代理：首字 1.534、1.559 秒；直连两次均在 4 秒连接限时超时。
- DeepSeek 系统代理：首字 1.002、1.299 秒；直连：1.869、0.543 秒。

诊断使用 4 秒连接、15 秒读取/写入/连接池限时，以控制无效等待；正式应用原有超时保持不变。这些结果仅说明当前网络下这两项直连未在诊断限时内接通，所以未为它们启用直连。

## 使用方式与实现

打开“问一问模型设置…”，选择模型，可勾选“此模型直连（跳过系统 HTTP 代理）”，点击“保存并使用”。每个模型独立保存，“沿用取词模型”也有独立的问答网络选择。旧配置和新配置默认继续使用系统代理；本次仅根据实测为当前官方 DeepSeek 配置设置直连，其他安装不会自动启用。

该选项只跳过应用为本次问答显式配置的系统 HTTP 代理，不修改系统代理、VPN 或 TUN。直连失败后可取消勾选再重试，不自动重复请求；TLS 验证保持开启。连接缓存同时包含网络选择，切换后不会复用旧路径。120 秒空闲连接复用、常驻引擎与原有流式输出保持。

改动文件：

- `ScreenshotQuestionPreferences.swift`：每模型及回退网络选择；更改思考强度保留网络选择；仅调整网络元数据时不访问 Keychain。
- `ScreenshotQuestionModelSettings.swift`：直连复选框、载入与保存。
- `ScreenshotQuestionBackend.swift`、`VocabCaptureApp.swift`：两个问答入口传递当前网络选择。
- `question-engine/question_engine.py`：严格校验布尔值，按路径选择客户端并隔离缓存。
- `QuestionNetworkTests.swift`、`question-engine/tests/test_engine.py`：默认迁移、独立保存、界面保存、三种接口单次请求与缓存隔离验证。
- `VERSION`、`README.md`、本记录：版本及使用说明。

复用现有配置、HTTP 客户端和连接缓存，没有新增依赖、模型调用或重试层。
