# 数学题库：本地数据库与原图

2026-10-09，照片优先的本地 MVP。复用截图问一问，无需独立数据库服务器、登录或云端题库。解题继续使用问一问中配置的模型。

## 使用

1. 菜单栏“截图问一问”框选一道题。
2. 可以直接点“保存题目”；也可以先点“解题”再保存。
3. 保存成功后点“查看已保存题目”，或从菜单栏打开“数学题库…”。
4. 题库支持按标题或 OCR 文字搜索、修改标题、查看完整原图、删除及撤销最近一次删除、重新索引、完整备份。

保存不调用模型，不要求 OCR 成功。生成中也能存图；完整回答产生后会追加到已保存的题目。失败、中断的回答不作为完整解题过程保存。AI 回答保留来源和未核实状态，不能当作学生作答或教师标准答案。

“解题”是普通快捷问题，与“解释这段话”等放在同一行，没有固定解题按钮。点击“编辑快捷问题…”可修改提问内容、改名或删除，保存后立即生效；用户已有配置原样保留。默认解题快捷问题会参考原截图，使用小学知识、不使用方程；这些要求同样可以由用户修改。保存题目独立于快捷问题，删除解题快捷问题也能继续保存原图。

## 数据位置与创建方式

首次保存题目或打开题库时自动创建：

```text
~/Library/Application Support/VocabCapture/math-questions/
├── questions.sqlite
├── questions.sqlite-wal  # SQLite 运行中的日志，可能存在
├── questions.sqlite-shm  # SQLite 运行中的协调文件，可能存在
└── assets/
    └── <SHA-256>.png     # 或 .jpg；不可变原图
```

原来的英文词库 `vocabulary.json` 与题库互相独立。数据库使用 macOS 系统 SQLite，没有下载新的依赖。API Key 保持在钥匙串，不存入题库。题目、索引、回答和照片保存在本机普通文件中。

当前数学题库没有云端同步，也不加入已有的英文词库同步流程。保存原图和建立本机 OCR 索引不会上传照片；用户提交参考截图的 AI 提问时，模型使用的派生截图会发送给所配置的模型服务。后续可扩展为可选云同步：本机保留离线副本，云端以私有文件存储保存原图、数据库保存题目/回答/标签及资产关联，按用户账号隔离。此方案尚未实现或开通。

截图以完整像素尺寸编码为无损 PNG 后保存；不使用发送模型的最长边 1600 像素派生图。Store 接收 PNG/JPEG 时保留输入原字节。这里的“原图”是用户本次框选所得的完整截图，不能恢复框外未提供的照片内容。

## 表结构

| 表 | 保存内容 | 关系与限制 |
|---|---|---|
| `image_assets` | 文件名、SHA-256、媒体类型、字节数、宽高 | 按实际图像字节去重，图片在 assets 文件夹中 |
| `questions` | ID、截图会话 ID、资产引用、标题、可选年级、创建/更新时间、删除时间 | 同一截图会话反复保存不创建第二道题；年级预留 1–6，不从 OCR 猜测 |
| `question_ocr` | 检索文字、pending/ready/failed、更新时间 | 每题一份可重建索引；内容为空也允许保存题目 |
| `question_solutions` | 轮次 ID、提问、完整回答、模型名、时间、来源、审核状态 | 每题可有多次回答，轮次 ID 防重复；AI 默认 unverified |
| `question_tags` | 维度、标签 ID、目录版本、显示名称、来源、确认状态 | 同一题可关联多个标签；目录更新不覆写旧标签含义 |

当前 UI 尚未提供年级和标签编辑。表中预留 `question_form`（题目形式）、`curriculum_knowledge`（课程知识点）、`problem_family`（问题模型）、`custom` 四种题目维度。错误形式、错误本质应关联具体学生作答；没有作答时不建立错因结论。学生作答、复习和错误分析表留到后续阶段。

下一阶段优先接入手动多维标签：保存后或在题库中补充题目形式、课程知识点和问题类型，允许多选；不要求先解题。之后再提供基于原图的 AI 标签建议，并由用户确认。错误形式和错误本质待学生作答/错误过程收集功能接入后记录，不能从题目原图或 AI 解题回答推断学生错因。标签目录目前仍为课标映射草案，题库尚未实际写入标签。

数据库 `application_id = 0x4D415448`，`user_version = 1`。当前仅支持首次建库与版本 1 的重新打开；后续版本应提供显式事务迁移。拒绝损坏数据库、其他应用数据库和更高版本，不清空或静默重建。所有 REAL 时间值采用 Foundation reference-date 秒，即从 **2001-01-01 00:00:00 UTC** 起计算，不是 Unix 秒。

## 保存、索引与一致性

原图通过 ImageIO 完整性检查，计算 hash，原子写入、同步文件和目录后，再用事务写入题目与资产关联。数据库开启外键、WAL、synchronous=FULL、5 秒忙等待；单个 actor 串行管理连接。只有原图和题目记录都成功才显示保存成功。若图像写入后数据库事务失败，可能留下未引用图像文件，不会出现成功记录指向未写入照片。

同一截图的重复操作只追加尚未保存的完整回答；不同截图即使照片字节相同也保留各自题目记录，共用资产。不会按 OCR 文本自动合并题目。删除是软删除，保留数据库记录和原图，可撤销；后续回答追加不会自动恢复已删除题目。

保存后由独立的本机 Vision 请求识别 `zh-Hans` + `en-US`。英文取词仍用原来的 `en-US` 请求，没有更改其识别配置。索引失败不改变原图或解题记录，用户可重新索引。初版搜索采用参数绑定的字面包含匹配，支持两字中文以及 `%`、`_` 等普通字符；暂未引入复杂的全文检索分词。

索引完成后，默认“未命名题目”会以 OCR 第一条中文文字行命名；没有中文时使用英文文字行。去掉开头题号，最多保留 32 个字符，较长时附加省略号。标题仅用于导航，完整 OCR 索引和原图仍保留；用户可在标题栏修改后按回车保存，手动标题不会被重新索引覆盖。打开旧库时也会补齐已有索引的默认标题，无需调用模型，也不改变数据库结构版本。

应用在首次保存后启动索引；若保存后应用立即退出、索引尚未完成，下次可从题库“重新索引”。原图已经落盘，不依赖后台任务完成。

## 备份与恢复

点击“完整备份…”并选择目标目录，会创建新备份文件夹，包含独立的 `questions.sqlite` 和全部关联 `assets/`，包括软删除记录。数据库使用 [SQLite Backup API](https://www.sqlite.org/backup.html) 获取一致快照，再按快照中的资产引用复制并验证原字节；不直接复制正在写入的 sqlite 文件，不覆盖已有备份目录。

完整备份可以在独立目录直接重新打开。当前版本没有一键覆盖恢复入口。需要恢复时先退出应用，将现有 `math-questions` 文件夹改名留存，再复制完整备份文件夹到该位置并命名 `math-questions`，最后重新启动应用。不要混合备份数据库与其他版本的 assets；不要在应用运行时只替换 sqlite 文件。

## 验证范围

自动测试覆盖原图保存、重新打开、完整备份、失败回滚、同图幂等、多次解答、空 OCR、索引失败、软删除/恢复、损坏/较新数据库拒绝，以及问一问生成与保存并发。可选样本验证读取本机外部目录，测试文件不进入用户题库或 Git：

```sh
MATH_ARCHIVE_SAMPLE_DIRS='/path/to/batch1/images:/path/to/batch2/images' \
  swift test --filter MathQuestionPhotoArchiveValidationTests
```

这证明存储保真，不等同于 OCR 全字准确、自动标签有效或解题正确。课程标签和错因分析仍属后续工作。
